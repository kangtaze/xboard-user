# Xboard Ferrari 项目功能结构文档

> 更新时间：2026-06-15

## 1. 系统架构概览

系统基于 Xboard（V2Board 二次开发）构建，包含三个独立的节点子系统：

```
┌─────────────────────────────────────────────────────────┐
│                      Xboard 后台                         │
│              (HK 服务器 154.3.38.212)                     │
│                                                          │
│  ┌──────────────────┐  ┌──────────────────────────────┐  │
│  │  Xboard Server   │  │      Edgetunnel 系统          │  │
│  │  (v2_server 表)  │  │  (v2_edgetunnel_* 表)        │  │
│  │                  │  │                               │  │
│  │  • CF Worker 节点│  │  • Edgetunnel 订阅导入节点     │  │
│  │  • 标准 V2Ray 节点│  │  • 67 个节点通过 eogop1      │  │
│  │                  │  │    .ferrari.cc.cd 代理        │  │
│  └────────┬─────────┘  └──────────────┬────────────────┘  │
│           │                           │                   │
│           └───────────┬───────────────┘                   │
│                       ▼                                   │
│              HookManager::filter                          │
│         ('client.subscribe.servers')                      │
│                       │                                   │
│                       ▼                                   │
│              用户订阅链接生成                              │
└─────────────────────────────────────────────────────────┘

┌──────────────────────┐     ┌──────────────────────┐
│  Edgetunnel Worker   │     │   CF Worker #1         │
│  eogop1.ferrari.cc.cd │     │   jpuuc.cc.cd          │
│                       │     │   (CfWorker ID=3)       │
│  67 个节点共用一个    │     │   独立域名/独立账号      │
│  Worker 代理          │     │   Server 节点 #85       │
└──────────────────────┘     └──────────────────────┘
```

### 组分配方式对比

| 子系统 | 组分配入口 | 存储位置 |
|--------|-----------|---------|
| Edgetunnel | Edgetunnel 后台页面 → 订阅编辑 | `v2_edgetunnel_subscription.group_ids` |
| CF Worker | **Xboard 后台节点管理 UI** | `v2_server.group_ids`（标准 Server 记录） |
| 标准 V2Ray | Xboard 后台节点管理 UI | `v2_server.group_ids` |

## 2. 数据模型关系

### 核心表结构

```
v2_server (Xboard 原生)
├── id, name, type(vless/vmess/trojan), host, port
├── group_ids (JSON array) → 控制哪些用户组可见
├── protocol_settings (JSON) → tls, network, path 等配置
├── tags → ["CF-Worker"] 标识 CF Worker 节点
└── 关联 CfWorker.xboard_node_id

v2_cf_worker (自建)
├── id, name, cf_account_id, cf_api_token, cf_zone_id, domain
├── worker_name → CF Worker 脚本名
├── kv_namespace_id → CF KV 命名空间
├── xboard_node_id → 对应 v2_server.id
├── group_ids (JSON array) → 部署时传给 Server
├── status → 0=未部署, 1=已部署, 2=错误
└── deployed_at, error_msg

v2_edgetunnel_subscription (自建)
├── id, name, url → Edgetunnel 订阅源 URL
├── group_ids (JSON array) → 控制哪些用户组可用
├── enabled, show → 启用/显示状态
└── last_sync_at

v2_edgetunnel_node (自建)
├── id, subscription_id (FK)
├── name, type, uuid, host, port, path, sni
├── host_header, fingerprint, security
├── enabled, show, sort, latency, online
└── 每个订阅导入的代理节点

v2_server_group (Xboard 原生)
├── id, name
└── 用户组（VIP1, VIP2 等）
```

### 模型对应关系

| 模型 | 表 | 文件 |
|------|---|------|
| `Server` | `v2_server` | `app/Models/Server.php` |
| `ServerGroup` | `v2_server_group` | `app/Models/ServerGroup.php` |
| `CfWorker` | `v2_cf_worker` | `app/Models/CfWorker.php` |
| `EdgetunnelSubscription` | `v2_edgetunnel_subscription` | `app/XboardFerrari/Models/EdgetunnelSubscription.php` |
| `EdgetunnelNode` | `v2_edgetunnel_node` | `app/XboardFerrari/Models/EdgetunnelNode.php` |
| `User` | `v2_user` | `app/Models/User.php` |

## 3. 节点订阅流程

### 用户订阅链接生成

```
用户请求订阅 URL
    │
    ▼
ClientController::doSubscribe()
    │
    ├── ServerService::getAvailableServers()
    │   └── 查询 v2_server WHERE group_ids 包含 user.group_id
    │   └── 返回标准 Server 节点（CF Worker 节点在这里）
    │
    ├── HookManager::filter('client.subscribe.servers')
    │   └── EdgetunnelServiceProvider 注册的 Hook
    │   └── EdgetunnelService::getAvailableNodes()
    │       └── 查询 EdgetunnelSubscription → 匹配 user.group_id
    │       └── 返回 Edgetunnel 节点（注入到订阅中）
    │
    └── 合并两组节点 → 生成 vless/vmess/trojan 链接 → Base64 输出
```

### Edgetunnel 节点域名分配

每个 Edgetunnel 节点的连接域名由 `assignDomainFromNodeName()` 决定：

```
节点名称: JP_日本_01 → 域名: jp01.eogop1.ferrari.cc.cd
节点名称: SG_新加坡_02 → 域名: sg02.eogop1.ferrari.cc.cd
无法解析的节点 → 通过 CF DNS IP→域名映射回退
```

SNI 和 Host header 统一为 `eogop1.ferrari.cc.cd`。

## 4. CF Worker 部署流程

### 部署步骤（CfDeployService::deploy）

```
1. 创建 KV Namespace
   POST /accounts/{id}/storage/kv/namespaces
   → title: edgetunnel-{worker_name}
   → 已存在则复用

2. 创建 Xboard Server 节点
   Server::create()
   → name: CF-{worker.name}
   → type: vless, host: worker.domain, port: 443
   → group_ids: $worker->group_ids ?: [2]（默认 VIP）
   → tags: ["CF-Worker"]

3. 上传 Worker 脚本
   PUT /accounts/{id}/workers/scripts/{name}
   → multipart: worker.js + metadata.json
   → 脚本来源: storage/app/worker-template.js

4. 设置 Worker 环境变量和 KV 绑定
   PATCH /accounts/{id}/workers/scripts/{name}/settings
   → multipart/form-data
   → Bindings: KV, UUID, ADMIN, XBOARD_NODE_ID, XBOARD_TOKEN, XBOARD_ORIGIN

5. 添加 Zone Route
   POST /zones/{zone_id}/workers/routes
   → pattern: {domain}/*, script: {worker_name}

6. 创建 Custom Domain
   PUT /accounts/{id}/workers/domains/{domain}
   → CF 自动处理 DNS，无需 Zone DNS 权限

7. 同步用户列表到 KV
   从已有 Worker KV 复制 user-list
   → 或从 Xboard 数据库查询有效用户生成
```

### CF Worker 页面入口

URL: `/api/v2/{secure_path}/cf-worker` → `cf-worker.blade.php`

## 5. Edgetunnel 订阅同步流程

### 同步触发

1. 手动：Edgetunnel 后台页面 → 点击"同步"
2. API: `POST /api/v2/{secure_path}/edgetunnel/subscription/sync`

### 同步流程（EdgetunnelService::syncSubscription）

```
获取订阅 URL 内容
    │
    ▼
解析 base64 编码的 vless/vmess/trojan 链接
    │
    ├── 自动创建 DNS A 记录（新 IP）
    │   → 格式: {region}{num}.eogop1.ferrari.cc.cd → IP
    │   → 只在 ferrari.cc.cd 的 CF Zone 创建
    │
    ├── 更新/创建 EdgetunnelNode 记录
    │
    ├── 清理不再存在的节点
    │
    ├── 清理不再使用的 DNS 记录
    │
    └── 清除 DNS 映射缓存
```

## 6. KV 用户同步流程

### KV 存储结构

```
KV Namespace: edgetunnel-{worker_name}
└── Key: "user-list"
    └── Value: ["uuid1", "uuid2", "uuid3", ...]  (JSON 数组)
```

### 同步方式

| 方式 | 入口 | 说明 |
|------|------|------|
| 单个同步 | CF Worker 页面 → "同步用户" 按钮 | `CfDeployService::syncUserListToKv()` |
| 批量同步 | `POST /cf-worker/sync-all` | 遍历所有已部署 Worker |
| 部署时自动 | `CfDeployService::deploy()` 步骤 7 | 从已有 KV 复制或从 DB 生成 |

### 同步逻辑

```php
// 获取所有有效用户（未封禁 + 未过期）
$users = User::where('banned', 0)
    ->where('expired_at', '>', time())  // Unix 时间戳比较
    ->orWhere('expired_at', null)
    ->get();

// 生成 UUID 列表（简单字符串数组，不是对象）
$userList = $users->pluck('uuid')->all();

// 上传到 KV
PUT /accounts/{id}/storage/kv/namespaces/{ns_id}/values/user-list
```

## 7. 组分配机制

### 工作原理

```
用户表 (v2_user)          节点表 (v2_server)
┌───────────────┐         ┌──────────────────────┐
│ group_id: 2   │──── match ──▶│ group_ids: [1, 2, 3] │ → 可见
│               │         │ group_ids: [1]         │ → 不可见
└───────────────┘         └──────────────────────┘
```

- 用户有**一个** `group_id`（属于单个组）
- Server/节点有**多个** `group_ids`（可分配给多个组）
- 过滤条件：`whereJsonContains('group_ids', (string) user->group_id)`

### 如何修改 CF Worker 节点的组分配

**直接在 Xboard 后台 → 节点管理中编辑即可。**

CF Worker 节点是标准的 Xboard Server 记录（`v2_server` 表），名称前缀为 `CF-`。
Xboard 后台的节点管理页面（`/server/manage`）原生支持编辑 `group_ids`：

1. 登录 Xboard 后台
2. 进入 **节点管理** 页面
3. 找到 CF Worker 节点（名称如 `CF-Cloudflare Worker02`）
4. 编辑节点的 **权限组**（group_ids 多选）
5. 保存即可生效

### Edgetunnel 节点的组分配

Edgetunnel 节点的组分配通过 **Edgetunnel 后台页面**（`/edgetunnel`）控制：
- 编辑 Edgetunnel **订阅**（不是单个节点）
- 设置订阅的 `group_ids`
- 该订阅下的所有节点对该组用户可见

## 10. 常见操作

### 添加新的 CF Worker 节点

1. 注册新 Cloudflare 账号
2. 添加域名到该 CF 账号
3. 创建 API Token（需 Workers Scripts + KV Storage + Zone 权限）
4. 在 CF Worker 管理页面添加账号
5. 点击"部署"
6. 部署成功后，在 **Xboard 后台 → 节点管理** 中找到新节点（名称 `CF-xxx`）
7. 编辑节点的**权限组**分配给目标用户组

### 修改 CF Worker 节点的用户组

直接在 **Xboard 后台 → 节点管理** 编辑 CF Worker 节点（名称前缀 `CF-`）的权限组即可。

### 修改 Edgetunnel 节点的用户组

在 **Edgetunnel 后台页面** 编辑对应订阅的权限组。

### 同步用户到 CF Worker KV

- 单个：CF Worker 页面 → "同步用户"
- 全部：`POST /{path}/cf-worker/sync-all`
